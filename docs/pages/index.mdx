# Stop Loss Documentation

A stop-loss order sells a token if its oracle price drops below the trigger price. It uses [Composable CoW](https://docs.cow.fi/cow-protocol/reference/contracts/periphery/composable-cow) to post an order on CoW Protocol. A stop-loss parent produces one CoW order, which can have partial fills.

## View your orders

Open the app directly and connect a browser wallet or use WalletConnect. A Safe connected through WalletConnect uses the Safe account address. You do not need to open the app inside Safe UI. This version is read-only: creation, review, and cancellation controls are unavailable.

The list combines the connected account's orders and its CowShed orders across Ethereum, Gnosis, Arbitrum, and Sepolia. Sepolia is marked as a testnet. Browsing does not switch your wallet chain. Filter by chain or status, then open an order's details to see its amounts, trigger and limit prices, oracle settings, and available execution data.

Orders load on connection and account changes. Use `Refresh orders` to get later changes. The app does not poll or refresh on focus or network reconnect. Expiry is calculated when data loads; there is no local expiry timer.

If one chain fails, its warning and retry button appear while other chains remain visible. A failed refresh can leave previously loaded orders visible with a warning that they may be out of date. Switching accounts or disconnecting clears the prior account's data. A detail link for another account asks you to connect that account before loading its orders.

## Prices and tokens

Trigger, limit, and execution prices are in buy-token units per sell token. Amounts use configured token decimals where available. Historical orders with unknown token metadata show raw base units instead of estimated token amounts. Execution fees also show raw base units because the order API does not supply the fee token.

The configured tokens and Chainlink price feeds remain unchanged:

| Chain | Sell tokens | Buy token |
| --- | --- | --- |
| Ethereum | WETH, WBTC | USDC |
| Gnosis | WETH, WBTC | USDC.e |
| Arbitrum | WETH, WBTC | Native USDC |
| Sepolia (testnet) | WETH | USDC (test) |

Production feeds quote prices in USD. Sepolia keeps its two fixed test feeds. Tokens and feeds are kept in the app repository and change with an app release. Viewing historical orders does not require their tokens to be in this configuration.

## Order data

The app reads all pages from the [programmatic orders API](https://programmatic-orders.cow.fi/graphql), including parents that have not triggered. It filters by chain, connected account or CowShed ownership, and the configured StopLoss handler: `0x412c36e5011cd2517016d243a2dfb37f73a242e7`.

State uses execution data and absolute expiry. Partially filled orders that were cancelled have a different label from partially filled orders that expired. Parent `Active` alone does not mean an order is still open.

## WalletConnect deployment

Set `NEXT_PUBLIC_WALLETCONNECT_PROJECT_ID` and `NEXT_PUBLIC_APP_URL` before building the app. Allow the deployed origin in your WalletConnect project settings. If no project ID is supplied, the app shows a configuration notice and offers only browser wallet connection. See the repository README for local setup and checks.

## FAQ

:::details[Can I create or cancel an order?]
This version only displays orders. It does not create, review, or cancel them.
:::

:::details[Do I need to switch chains to view orders?]
No. All supported chains are loaded together. Enable testnets in your wallet when needed, but Sepolia orders remain visible without switching the wallet chain.
:::

:::details[Will viewing orders move my tokens?]
No. Connecting and viewing orders does not submit a transaction or move tokens.
:::

:::details[Where can I learn about CoW hooks?]
See the [CoW Hooks documentation](https://docs.cow.fi/cow-protocol/reference/contracts/periphery/hooks-trampoline). This read-only app does not configure hooks.
:::
